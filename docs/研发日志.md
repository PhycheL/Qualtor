## 2026-10-27：处理首轮 Docker 标定发现的问题

- **起因**：用户在 Linux ARM64 Docker 中完成 102 道新题的全量标定（`runs/bank-prepare-20261027-01/`）：98 道写入分母，4 道未通过；另有 2 道题覆盖率不可用，13 道原始检出率低于 0.8。
- **第 17 组崩溃**：`minPath` 的网格不含 1 时读取未初始化的 `x`、`y`。原生成器的两遍填充都给出 0 或负值，恰好不越界，两遍结果一致而被保留；到 Linux 上读到正的垃圾值，越界崩溃。改为带 ASan 与不带 ASan 两种构建、4 种填充共跑 4 遍，只保留每遍都正常结束且结果相同的输入；全部生成型题按新规则重建，其中第 02、15、17 组的测试有变化（第 15 组去掉了 `maximum` 的 50 个越界输入），其余 17 组与首轮完全相同。
- **零变异与头文件题**：hello-world、reverse-string 在当前算子下没有变异，linked-list 的 `.cpp` 是空壳。三题移出题库，导入脚本写明排除原因并增加空壳检测；零变异题口径作为 R-06 的一部分提出。
- **覆盖率**：评测模块升为 0.1.6，修正两处解析问题：gcov JSON 同一行多条记录（析构函数 D0/D2）按行合并、函数按名称与起始行合并、文本只取合并行；只有 `.gcno` 没有 `.gcda` 的被测源文件按 0/0 计入。新增 `CoverageMergeTest`，用该轮 tennis4 的真实 gcov 输出作夹具。待在 Docker 中重新校准。
- **失误与补救**：重建时导入脚本会先删除整个题目目录，一并删掉了用户写入的分母。材料未变的题已从首轮标定的草稿逐字节恢复，材料变化的题需要重新标定；`bankutil` 改为重建时自动保留材料未变题目的分母。
- **复核辅助**：新增 `benchmark/tools/mutant_report.py`，逐题列出等价候选、不稳定、探针超时和参考测试缺口，附源码行与变异后写法。
