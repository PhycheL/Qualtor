## 2026-10-24：Docker 完整校准与成本修复

- 按[评分器运行说明](评分器运行说明.md)在 Linux ARM64 Docker 中执行。固定镜像标签最初不存在，按现有 Dockerfile 复用缓存构建，两套工具链各 9/9 测试通过。镜像定义、被测源码、校准样本和阈值均未改动。
- 参考强测试与有界穷举探针各评两次，47 个变异全部检出；等价候选、不稳定和需复核均为 0，替换版本准入通过。分母写入题目包，自动生成的人工复核字段保留 `pending`。
- 原版 0.1.0 的 16 个样本均满足既有校准期望，但检查原始结果发现 CAL-01 至 CAL-06 的成本全为 `null`。根因是无效产物提前返回，跳过了末尾的成本读取；K1 汇总会漏计失败生成的成本。
- 先用回归测试复现，再将成本读取移到提前返回之前；校准器逐轮核对 `cost`、`metrics.K1` 和输入成本。版本升至 **0.1.1**，59 个单元测试通过，1 个未配置的宿主机集成测试跳过。新检查回放旧结果，准确指出前 6 个样本的成本缺失。
- 修复后重新完整校准：16 个样本各 2 次，全部通过且结果一致；CAL-12/13、CAL-14、CAL-15 的 M1 分别为 3/47、8/47、47/47，行覆盖均为 29/29。CAL-07 的无效测试过滤、崩溃与超时定位、稳定性和等价版本误报判定均符合期望。
- 命令行验收通过：冻结、单份评分、补评、汇总、比较，以及重复冻结、重复运行 ID、重复 trial、未校准结果、篡改产物的拒绝。用非零合成成本确认编译失败产物的 K1 仍被汇总；比较输入为校准样本副本，不代表 Agent 生成效果。

证据：[分母准入报告](../gildedrose-lab/runs/scorer-docker-prepare-20261024-01/prepare_report.json)、[0.1.1 校准报告](../gildedrose-lab/runs/scorer-docker-calibration-20261024-02/calibration_report.md)、[命令行检查](../gildedrose-lab/artifacts/scorer/docker-validation-20261024/cli-checks.json)、[完整审计](../gildedrose-lab/artifacts/scorer/docker-validation-20261024/)。历史失败和 0.1.0 结果保留原样。

### 过程

1. **核对现状**：读评测规格 v0.3、评分算法、评分器设计，以及现有的 `toolchains.py`、`check_toolchain.py`、`Dockerfile.toolchains` 和冒烟样例。确认本机无 Docker，询问用户后确定上述方案。
2. **动手前先核对关键事实**，不靠猜：
   - mull-runner 的用法为 `[OPTIONS] <EXECUTABLE> [RUNNER_ARGS]...`，测试参数可以跟在可执行文件后面传入（Mull 0.34.2 文档）。因此改用 `--gtest_filter` 参数只运行有效测试，不再依赖环境变量。
   - Mull Elements 报告中变异的 `id` 形如 `cxx_sub_to_add:/repo/cpp/src/GildedRose.cc:51:47:51:48`，可以直接作稳定标识；gcov 14.2.0 的 JSON 带 `functions` 字段，可以算函数覆盖。两者都取自工具链验收轮次 `cxx11-final-20261023` 在容器里生成的真实报告。
   - GoogleTest 1.12.1 的行为（本机实测）：列表 JSON 包含禁用的测试；跳过为 `RUN/SKIPPED`，禁用为 `NOTRUN/SUPPRESSED`；只有出现失败时退出码才是 1；标准输出里每个测试的结束行带 `(N ms)`，汇总段的同名行不带。
   - GoogleTest 会忽略单独的 `--`，后面的过滤参数照常生效。所以不管 mull-runner 会不会原样转发 `--`，都不影响只运行有效测试。
3. **搭本机临时环境**：venv + cmake/ninja，下载并校验 GoogleTest 1.12.1 后构建。顺带用它验证了评分器的 CMake 模板（plain 模式）。
