# C++11 Docker 工具链运行说明

当前只保留 [`toolchains.py`](../gildedrose-lab/toolchains.py) 这一运行入口。它在宿主机构建两套镜像，再分别启动容器验收：GCC/gcov/GoogleTest 负责测试和覆盖率，Clang/Mull/GoogleTest 负责测试和变异分析。每个镜像本身都能编译、运行测试；当前没有额外的测试运行镜像。

本文路径默认相对 `gildedrose-lab/`，命令从项目根目录执行。完整版本、参数、项目接入方式和验收证据见 [C++11 固定工具链](C++11固定工具链.md)。

## 运行

前提：Docker 已启动、宿主机 Python 3.9+，仓库内已有 `external/GildedRose-Refactoring-Kata/cpp/` 和 `external/source_manifest.json`。入口校验现有快照，不自动克隆或更新上游。首次构建需要联网，验收容器禁网。

```bash
python3 gildedrose-lab/toolchains.py
```

默认构建并验收 GCC、Clang 两个镜像。镜像已存在时加 `--skip-build`；只构建时加 `--build-only`；只选一套时加 `--toolchain gcc` 或 `--toolchain clang`。

每轮使用新的运行目录，也可传 `--run-id my-experiment`，已有 ID 会被拒绝。源码和测试只读挂载到容器，输出写入独立目录；执行前后校验上游源码哈希。

当前验收用同一份 `cpp/src/GildedRose.cc` 和 9 个手写 GoogleTest 测试，验证 C++11 编译、测试发现与执行、GCC 覆盖率和 Mull 变异。`status: passed` 表示工具链验收通过；模型测试生成与修复仍待实现。评分器已基于这两个镜像实现，用法见[评分器运行说明](评分器运行说明.md)。

## 当前目录

| 路径 | 内容 |
|---|---|
| `toolchains.py` | 宿主机构建镜像、启动容器、汇总结果 |
| `docker/Dockerfile.toolchains` | `gcc`、`clang` 两个最终镜像的构建定义 |
| `docker/.dockerignore` | 构建上下文过滤规则；项目源码不打入镜像 |
| `scripts/check_toolchain.py` | 容器内工具链验收 |
| `scripts/audit.py` | 命令和输出审计，供宿主机与容器复用 |
| `scripts/coverage.py` | gcov 文本、JSON 解析与计数核对 |
| `scripts/source_snapshot.py` | 上游源码范围和哈希校验 |
| `toolchains/smoke/` | C++11 GoogleTest 测试、CMake 与 Mull 配置 |
| `external/GildedRose-Refactoring-Kata/cpp/` | 固定的上游 C++ 源码、头文件和构建配置 |
| `external/source_manifest.json` | 上游提交、cpp 范围和 20 个文件的 SHA-256 |
| `runs/<run-id>/` | 本轮汇总以及 `gcc/`、`clang/` 各自的测试和分析结果 |
| `artifacts/toolchains/<run-id>/` | 输入哈希、构建日志、镜像和容器证据 |
