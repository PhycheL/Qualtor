## 应该修的缺陷

1. **生成的测试能让整个 run 永久挂死**（`evaluator/common/audit.py:67-74`）：
   - 进程正常退出后，`audit.py` 会一直等输出读完、没有超时；测试只要留一个持有 stdout 的后台进程，就永远等不到结束。
   - `extension.ts:80` 每 30 秒发一次"仍在运行"事件，这会刷新看门狗计时（`launch.py:77`），15 分钟的看门狗永远不会触发。
   - 宿主机这边 `host.py:226` 用的是 `timeout=None`，所以整个 run 一起挂住。
   - 模型写出这种测试的概率不高，但一旦发生就没有任何兜底。
2. **一个 trial 抛出基础设施异常后，其余 trial 照常跑完**（`run.py:70-73`）：异常要等所有 trial 结束才抛出来，期间其余 trial 继续消耗模型费用，最后 run 记为失败，`summary.json` 也不会写出。
3. **反馈截断可能把测试结果截掉**（`build_service.py:88`）：程序先把每个测试的完整输出拼起来，再整体截到 8000 字符。测试多或者输出长的时候，排在后面的测试连通过还是失败都看不到，这违背了设计里"返回每个测试的状态"。改法是把通过/失败汇总放在最前面。
4. **自测里有两条隔离断言检查不到任何东西**（`scenarios.py:45-46`）：它们检查的 `/scorer/...`、`/lab/...` 是重构前的路径，新布局里根本不存在，所以这两条断言无论如何都会通过。实际的隔离靠"不挂载"保证，没有问题，但这两条断言起不到证明作用。

还有几处值得改，但不急：
- 补评中途失败后不能续跑（`score.py:34,68`）；
- 补评时校准状态不是 passed 只给警告，不拒绝；
- `tests/` 和会话目录没有容量上限；
- pi 的 `node_modules` 不计入版本哈希；
- 门卫的 TS 代码没有单元测试。

## 需要你决定的两个评测设计问题

**A. eq-01 误报其实是题目和评分规则的问题，不是测试写错。** 12 份产物在 eq-01 上全部判为误报，最终产物的 F1 最高到 0.30。
- 原因：eq-01 会把质量截断到 0–50，只在评分输入域内和原代码等价。而误报的断言全部落在评分域之外，比如质量 60、-3，期望值正是原代码的真实输出。按 D001，这些测试并没有写错。
- 但评分域对 Agent 不可见（`TASK.md` 里没写），评分器也不把域外断言单独计数。所以现在的 F1 量的其实是"测了多少域外输入"，而 CAL-16 又把这种情况固定成了误报。
- 可选做法：
  - 把输入域写进 `TASK.md`；
  - 把等价版本改成在全部输入上等价；
  - 只用落在评分域内的测试计算 F1。

**B. GildedRose 已经区分不出 Agent 的好坏。** 12 份产物的 M1、C1、C2、M2 全部是满分（47/47 个变异全部检出），首次产物也是满分。主指标在这道题上已经到顶，以后改 skill 也看不出差别，需要尽快补更难的题。
