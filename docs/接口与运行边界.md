# 产品接口与运行边界

本文供项目维护和接口接入核对；独立交付的安装、使用与状态处理集中在[产品 README](../agents/README.md)。以下路径以仓库根目录为起点，产品独立使用时从产品目录执行 `python3 run.py`。

公开入口为 `python3 agents/run.py --task <任务文件> --output <新目录> [--config default] [--env-file <文件>]`。`--describe` 输出接口版本、无密钥的配置、产品指纹及宿主机 pi 安装记录。接口和结果的 `schema` 当前为 1。

## 编译工具与调用流程

`build_and_test` 是产品通过 pi 的 TypeScript 扩展注册的工具，由模型主动调用。Hook 用于启用工具、检查调用和记录事件；编译在工具执行函数收到调用后开始。工具通过本地 Unix socket 请求宿主机 Python 编译服务，由服务保存本轮测试快照、启动 GCC Docker 容器并收集结果。

每次编译前保存本轮测试快照，容器使用这份快照编译和运行。结果文件写入后，工具将摘要、完整反馈文件路径和剩余修复轮次返回给 pi；模型据此继续修改测试或结束任务。首次编译不计修复，以后每次编译消耗一轮修复预算；预算用完后拒绝新的编译请求，等待 Agent 结束或触发无响应终止。

## 输入与产物

任务包含[产品 README](../agents/README.md#公开任务和生成)中列出的九个必填字段，以及可选 `build`（D017）、`target_headers`（D018）。runner 只在题目存在这些字段时投影；`build` 子字段、白名单和缺省规则见产品 README。宏名及标识符形式的宏值拒绝 `__*`、`_[A-Z]*`、C/C++11 关键字、替代记号和 `defined`。产品拒绝隐藏评分字段及其他未知字段；`visible_files` 只接受普通文件，禁止越界和符号链接。`allowed_test_files` 限于 `tests/` 下的路径，支持 `*` 匹配子目录；被测与依赖文件都必须可见，彼此互斥。修复轮数为非负整数，单测超时为有限正数。

纯头文件题使用空 `target_sources` 和非空 `target_headers`，后缀限 `.h`、`.hh`、`.hpp`、`.hxx`、`.inl`。暂不接受同时有被测源文件和被测头文件的混合题。产品 TASK.md 列出被测头文件并说明被测代码全部位于其中；普通源码题的 TASK.md 不变。`coverage_baseline.json`、准备阶段实例化文件及其他隐藏材料不会进入公开任务和生成工作区。

模型配置含 provider、model、thinking、API 类型、连接字段名、上下文与输出上限、兼容设置和可选单价。连接文件按单行字面值解析，不执行 shell 或插值；缺字段直接失败，不回退到旧环境变量。快照保存地址和字段名，不保存密钥。默认 `.env` 位于产品目录，与启动目录无关。

编译前保存本轮测试快照，具体是将当前测试复制到 `attempts/attempt-N/product/`，记录每个文件的 SHA-256，并将测试副本设为只读。Agent 仍可修改 `workspace/tests/`，本轮编译和反馈始终对应已保存的副本。第 1 次快照同时保存到 `first/`，结束时另存最终测试快照到 `final/`；从未编译时两者都取结束时内容。若 Agent 在最后一次编译后继续修改测试，最终快照可能未编译；生成状态与质量判定分别处理。预算和快照清单位于 Agent 工具不能访问的工作区外。

`result.json` 保存结束状态、编译/修复次数、生成尝试次数、失败记录、成本、宿主机运行方式和 GCC 镜像 ID。`generation-attempts/` 保留每次完整生成；根目录提供最后一次尝试的副本。成本从完整 assistant 消息提取，不累加流式增量；首次和最终成本都包含此前失败尝试的消耗。

实现入口为 `agents/generator/runtime/extension.ts`（注册工具和 Hook）、`agents/generator/build/service.py`（宿主机编译服务）；`evaluator/runner/` 只经产品公开 CLI 接入。

## 宿主机 pi

Python 启动宿主机 Node/pi，使用独立状态与会话目录，禁用自动发现的扩展、MCP、skill、上下文文件、提示词模板及内部重试；只加载产品指定的扩展。凭证仅按选中配置传入 pi。安装清单记录并校验 Node、操作系统、CPU 架构、源码、构建输出、依赖内容和搜索工具。

七个工具为 `read`、`write`、`edit`、`grep`、`find`、`ls`、`build_and_test`。文件工具只访问本次 `workspace/`，写操作只修改允许的测试。工作区只包含可见源码副本、任务说明、测试和本次编译反馈。源码副本只读并校验前后哈希；测试写入总量限制为 64 MiB。`write` 和 `edit` 共用最终文件写入检查，按 pi 处理完批量替换、BOM 和换行后的 UTF-8 字节数计算；配额检查与写入同步执行，避免并发超额，拒绝时保留原文件。

这些规则限制模型通过工具执行的操作。pi 使用宿主机用户身份，**不构成恶意 pi/扩展的操作系统隔离**。宿主机状态、会话和日志保存为普通文件，不再使用旧版内存文件系统的容量配额。

## Docker 与反馈

每次编译创建全新 GCC 容器：可见源码挂到 `/project`，本轮测试快照挂到 `/product`，均只读；CMake、可信服务和公开编译参数也只读。容器不挂入 pi、连接文件、整个仓库或评分材料。

容器禁网、根文件系统只读，限制 2 CPU、2 GiB 内存、256 个进程。可信监督程序用 root 降权和清理；编译器与生成的 C++ 使用 UID 65534。工作目录位于 512 MiB 的 `/tmp`；日志挂载位于 Linux 原生的 root 私有父目录 `/private/` 之后，避免 Docker Desktop 权限映射让测试改写审计。每个命令结束后清理测试 UID 的残留进程，最终删除容器。

普通模板使用 GCC 14.2.0 / GoogleTest 1.12.1；C++ 固定 C++11，C 源文件按题目声明的 c99/c11 编译，均关闭语言扩展。依赖源文件一并编译链接，宏和选项作用于全部编译单元，不含评分插桩。配置和编译分别限制 300、900 秒；每个测试按任务超时单独执行一次，整个编译容器另有 1800 秒故障上限。完整 stdout、stderr、退出码和测试 JSON 保存在 `attempts/attempt-N/output/`，副本投影到 `workspace/feedback/attempt-N/`，供 Agent 继续读取。

工具返回通过/失败汇总、所有未通过测试的名称、失败详情和剩余轮数。详情按 8000 字符截断，失败名单完整保留；编译错误摘要也按 8000 字符截断，完整输出落文件。反馈只包含本次编译执行结果。

## 结束与重试

| 状态 | 含义 |
|---|---|
| `finished` | pi 正常结束，不表示测试质量已经通过评测 |
| `budget_exhausted` | 已用完首次编译及所有修复编译次数 |
| `never_built` | 未调用编译工具 |
| `generation_stalled` | 无进展超过看门狗阈值，默认 900 秒 |
| `agent_error` | pi/API/编译基础设施错误，最多三次完整生成尝试 |
| `cancelled` | 用户发送 SIGINT / SIGTERM，保留已有产物与已记录成本，不重试 |

看门狗在编译忙碌时暂停，编译心跳不算模型进展；编译受阶段与容器超时控制。编译失败或断言失败是反馈给 Agent 的正常结果，不触发全新生成。CLI 正常结束返回 0，重试耗尽的 `agent_error` 返回 1，输入或启动检查失败返回 2；调用者读取结果区分具体状态。

取消信号由产品 CLI 传给监督进程，监督进程结束 pi，并通知编译服务收尾、删除 Docker 容器。首次/最终快照和成本随后落盘；SIGINT、SIGTERM 对应 CLI 返回 130、143。`result.json.cancellation_signal` 保存入口收到的信号；`runtime.json.product_pid` 和监督日志中的 PID 用于执行审计。强制 SIGKILL、宿主机故障不属于可执行清理的信号路径。

在成本提取或证据复制期间取消，同样记为 `cancelled`，不再重试。根目录的 `generation.json`、`result.json` 记录整个产品调用的状态；`generation-attempts/` 中的原始状态保留单次监督进程结束时的事实，因此收尾期间取消时两者可能不同。

`--scenario` 用于框架验收，通过真实 pi 的本地 provider 执行工具剧本，不调用付费模型；`--attempts 1` 关闭全新生成重试。框架自测与真实模型结果分别报告。
