# 测试生成入口与受限工作区运行说明

生成入口是 `evaluator/generator/run.py`，直接调用仓库里的 pi，不加载 skill。每个 trial 从空工作区开始，由 pi 自己决定生成与修复；结束后自动冻结首次、最终两份测试，分别评分，再按开发集和验收集汇总。

## 1. 准备环境

从仓库根目录运行，宿主机需要 Python 3.9+ 和 Docker：

```bash
python3 evaluator/toolchains/toolchains.py
python3 evaluator/scorer/calibrate.py
```

默认构建 GCC、Clang、generator 三个镜像。生成镜像固定 Node 24.10.0，沿用 GCC/C++11/GoogleTest；pi 和依赖在宿主机 `agents/pi/` 中构建，运行时只读挂载。

只重新构建 pi 与生成镜像：

```bash
python3 evaluator/toolchains/toolchains.py --toolchain generator
```

入口执行 `npm ci --ignore-scripts`，再按 pi 源码的 `nix/model-catalog.json` 下载并校验内容寻址的模型目录，执行 `build:offline`。普通 `npm run build` 会刷新实时目录，可能引入与源码不兼容的模型类型，因此不用于这里的复现构建。不会修改 pi 已跟踪的源文件。`node_modules/`、`dist/` 和 `.qualtor-build.json` 不入 Git；源码、锁文件和 `UPSTREAM.json` 入库。pi 或生成镜像改变后，生成入口会要求重新构建。pi 的运行时指纹除源码和 `dist/` 外，还包括各 `node_modules/` 的元数据（路径、大小、修改时间），依赖被改动、增删也会被发现；2026-10-25 起旧的构建记录需要重新运行一次 `--toolchain generator`。

镜像和 pi 已构建时，可用 `--skip-build` 验收。生成镜像冒烟通过真实 pi 的剧本 provider 运行 9 个手写测试，不访问真实模型。

## 2. 填写模型配置

[默认配置](../agents/configs/default/config.json) 已按用户选择设置为 `cc-switch-tencent-token-plan` / `deepseek/deepseek-flash`，thinking 为该模型支持的最高级别 `max`。接口兼容参数、上下文与单响应输出上限沿用本机 pi 的该模型配置。`thinking_level_map` 传给 pi 的 `thinkingLevelMap`；最高级别必须在映射中声明，否则 pi 会把它限制到模型默认支持的级别。

切换模型时一并调整 `provider`、`model`、`api`、`thinking`、`reasoning` 及兼容参数。API 地址和密钥从**仓库根目录的 `.env`** 读取。首次配置先复制[示例文件](../.env.example)，再填写密钥：

```bash
cp .env.example .env
```

```dotenv
QUALTOR_API_BASE_URL=https://api.lkeap.cloud.tencent.com/plan/v3
QUALTOR_API_KEY=填写实际密钥
```

`base_url_env`、`api_key_env` 指定 `.env` 中的字段名，默认含义是：

- `QUALTOR_API_BASE_URL`：模型服务的 API 根地址；不能包含用户名、密码或查询参数。
- `QUALTOR_API_KEY`：密钥；仅放在本机 `.env`，不写入模型 JSON 配置或提交到仓库。

无需 `export` 或 `source .env`；入口固定从仓库根目录读取，与启动时的工作目录无关。文件值覆盖同名进程环境变量；文件缺失、字段缺失或为空时直接报错，不回退到旧环境变量。支持空行、`#` 注释、`KEY=VALUE` 和单/双引号包裹的单行值；未加引号的行尾注释须以空白加 `#` 开始。值按字面读取，不执行 shell、不做变量插值或反斜杠转义。

`.env` 和 `.env.*` 已加入 Git 忽略，只有 `.env.example` 入库。入口只把选定的连接字段传给自身进程，Docker 再按名称接收密钥；不会把 `.env` 挂进容器、复制到 run 或写入日志。`.env` 中其他设置不会导出到宿主机环境。

`cost_per_million` 可填写 pi 的 `input`、`output`、`cacheRead`、`cacheWrite` 单价。当前没有配置单价，USD 成本记为 `null`，仍记录 token、模型调用数、时间和修复轮次。模型配置或 `.env` 配置缺失时，入口在调用模型之前退出。

复制 `agents/configs/default/` 为另一个名称可新增配置。当前配置只接受模型设置，不支持额外工具、skill 或任意执行命令。

## 3. 一条命令运行

```bash
python3 evaluator/generator/run.py --config default \
  --tasks gildedrose-update-quality --set dev --trials 5 --jobs 1
```

- `--tasks` 接受一个或多个题目 ID、逗号分隔列表，或 `all`。
- `--set dev|acceptance` 可选；不指定时分别汇总各集合，永不合并。
- 默认每题 5 个 trial、串行；`--jobs` 控制 trial 并发。
- `--run-id` 可自定义；已有目录拒绝覆盖。
- 当前评分器、样本、题目或镜像不匹配校准记录时，入口拒绝生成；先重新校准。
- 某个 trial 出现基础设施异常（例如 Docker 创建容器失败）时，立即取消所有尚未开始的 trial，避免继续消耗模型费用；正在运行的 trial 跑完后保留结果，`summary.json` 记为 `failed` 并列出异常和被取消的 trial。
- `run.json` 的 `kind` 只取 toolchain、prepare、calibration、eval 四类，`status` 只取 running、completed、incomplete、failed；验收类执行的结论另记在 `passed` 字段。

每题的 `budget.repair_rounds` 当前为 3。第一次 `build_and_test` 冻结首次产物，不算修复；总共最多执行 4 次，后续请求拒绝执行。用满预算后允许 pi 自行结束，结束时记为 `budget_exhausted`；最终产物可能包含最后一次验证后的编辑，独立评分会检验这些编辑。未编译就结束记为 `never_built`，首次和最终使用结束时的相同内容。

连续 15 分钟无 JSON 事件时终止 pi，记为 `generation_stalled`，冻结当时产物并评分。API/进程错误记为 `agent_error`，用全新工作区最多重跑 2 次；三次都失败时记为缺失，所有尝试和费用保留。没有 token 或总墙钟预算。

## 4. 隔离和编译反馈

容器内工作区是 `/workspace/project/`、`tests/`、`TASK.md`。源码按 `visible.files` 逐文件只读挂载，没有把整个源码目录或仓库挂进去；上游测试、参考测试、替换版本、分母和旧运行记录不会进入生成容器。

pi 只有 read/write/edit/grep/find/ls/build_and_test。框架扩展阻止工作区外读取、源码修改、不符合 `allowed_test_files` 的写入和符号链接路径；禁用上下文文件、扩展自动发现、MCP、skill、提示词模板及启动联网检查、遥测。

扩展把编译请求交给容器内可信监督服务。服务维护预算、首次快照和尝试记录；共享记录挂载在 root 私有的 Linux 原生父目录后。Agent 可写的 `tests/`（64 MiB）、pi 状态（16 MiB）和会话（256 MiB）都是限定大小的 tmpfs，写满时写入失败、不会占满宿主机磁盘，生成结束后由监督进程只把普通文件复制回 trial 记录；编译用只读快照放在 Linux 原生临时目录中；pi 与编译/测试进程使用不同 UID，测试进程不继承模型凭证，不能写预算或冻结快照，也不能读取 pi 状态。监督进程只保留降权、文件权限和终止子进程所需的 capabilities；容器根文件系统只读，限制 2 CPU、2 GiB、256 进程。评分容器仍保持原来的非 root、全 capabilities 丢弃、禁网规则。

`build_and_test` 复用评分器的 CMake 模板，GCC plain 模式，不插桩。按发现顺序，每个测试单独启动一次并使用题目单测超时；不重复、不乱序。每个测试结束后清理测试用户的全部残留进程，测试留下的后台进程不会让编译服务卡住。反馈最多 8000 字符加剩余轮次：测试结果先给通过/失败汇总并列出每个未通过的测试，再附失败详情，截断只发生在详情部分；完整编译/运行输出另存。只反馈编译和测试结果，评分发生在生成容器结束、产物冻结之后。

生成容器直接联网，测试进程也可联网；评分时禁网。这一差异按设计保留，当前题目不依赖网络。

## 5. 结果与成本

```text
runs/<run-id>/
  run.json
  evidence/
  trials/<task-id>/trial-<k>/
    TASK.md  input/  workspace/tests/
    attempts/attempt-<n>/       # 每次编译前快照、完整日志、结果
    first/  final/              # manifest、SHA-256、测试文件
    logs/                      # pi JSONL、stderr、原始会话、裁判与容器日志
    generation-attempts/       # 所有生成尝试原位保留；包括基础设施失败
    generation.json  trial.json
    cost.json  cost-first.json  cost-final.json
    score/<scorer-version>/first/  final/
  summary.json
```

成功尝试复制到 trial 根供阅读和评分，原始尝试目录保留，所以审计中的原始宿主机路径仍可访问。编译尝试数、修复轮次、测试函数数、trial 数分开记录。

`run.json` 保存 Qualtor 提交与未提交改动哈希、pi 源码和运行文件哈希、配置、API 地址、题目指纹、镜像 ID、评分器与校准状态、时间、结束状态；不保存密钥。Docker inspect 日志排除凭证环境，pi 输出和会话中的实际凭证值被替换。

`cost.json` 从会话原文派生，带抽取脚本版本；首次截止第一次 build_and_test，最终截止生成结束。统计输入、输出、缓存读写 token，assistant 消息数、实际修复轮次、墙钟秒数、pi 费用。重试消耗计入成本；`summary.json` 的 `all_generation_cost` 还包括最终失败的 trial。

单次生成尝试可重新提取成本：

```bash
python3 evaluator/generator/cost.py runs/<run-id>/trials/<task-id>/trial-1/generation-attempts/attempt-1
```

未配置价格时加 `--unpriced`；该命令输出 JSON，不覆盖已有成本或评分。

## 6. 补评与框架自测

升级并校准评分器后，在原 run 中补评，不重新生成：

```bash
python3 evaluator/scorer/score.py --rescore <run-id>
python3 evaluator/scorer/aggregate.py summarize --runs <run-id> --scorer-version 0.1.3 --phase final
```

产物篡改会被拒绝，评分器校准状态不是 passed 时默认拒绝补评；新版本结果写入各 trial 的 `score/<新版本>/`。补评中断后重跑同一命令即可续跑：已有有效结果的跳过，未完成的移入 `incomplete/` 后重评。汇总指定评分器版本；基础设施重试和被移开的结果不重复计入。

完整剧本验收与正式编排器的 K=5 自测：

```bash
python3 evaluator/generator/selftest.py
python3 evaluator/generator/selftest.py --closed-loop --trials 5 --jobs 2
python3 -B -m unittest discover -s evaluator/generator/tests -v
```

剧本覆盖正常完成、错误断言/编译错误修复、预算耗尽、从不编译、无事件卡死、API 出错后成功重跑、持续出错到重试上限、越权工具调用及编译子进程权限。看门狗自测缩短为 8 秒；正式生成固定 15 分钟。看门狗只在没有编译任务时计时，`build_and_test` 运行期间的进度心跳不刷新计时，编译和测试由各自的阶段超时约束。越权场景和进程隔离场景另外核对生成容器 inspect 记录中的实际挂载来源，隐藏材料、校准样本及其上级目录、其他 run 都不能出现。剧本费用和生成质量不代表真实模型。

## 7. 本轮验证与范围

本轮在 Linux ARM64 执行；AMD64 尚未实测。生成镜像 9/9、10 个剧本场景、K=5 自动闭环、16 个样本各两次校准均通过；补评和命令行 21 项检查通过。另用本地模拟 HTTP API 验证了 pi 实际客户端、凭证传递与脱敏；它仍不是模型质量验收。实现与原始结果见[研发日志](研发日志.md)。

真实运行 eval-pi-deepseek-flash-max-20261024-01（`runs/eval-pi-deepseek-flash-max-20261024-01/summary.json`） 使用上述默认配置，串行完成 5 个 trial，首次与最终共 10 份产物均为 `scored`，无 API 重试或人工修改。全程约 504.8 秒；生成累计 48 次模型调用、439.1 秒，额外编译验证轮次合计 5。首次编译均通过，因此错误修复路径由剧本场景另行验证。

10 份产物均检出 47/47 个冻结变异，行/分支覆盖为 29/29 和 38/38；等价版本误报率 F1 的首次均值为 6.70%，最终均值为 11.00%，完整结果原样保留。这次运行验证入口闭环，不能仅凭满覆盖和满变异检出得出模型质量优胜结论。

该次 K=5 验收从本机 pi 的指定 provider 配置读取凭证，仅注入 `QUALTOR_API_BASE_URL` / `QUALTOR_API_KEY` 子进程环境，未复制宿主机状态与会话；当前入口已改为从 `.env` 读取，配置方法见第 2 节。历史启动代码、时间与退出码保存在该 run 的 `evidence/launcher.py` 和 `launcher.json`；49 项完成核对（`runs/eval-pi-deepseek-flash-max-20261024-01/verification.json`）确认冻结哈希、成本重算、各会话 `max`、代码指纹一致，且产物和日志中没有凭证值。

`.env` 迁移后，在清除这两个启动环境变量、工作目录为 `/private/tmp` 的条件下，用正式 CLI 完成了 1 次真实模型闭环（`runs/eval-dotenv-20261024-02/summary.json`）：首次测试失败后自动修复，共 3 次编译验证、2 个修复轮次，首次与最终产物均完成评分。生成器 11 项单元检查通过；17 项完成核对（`runs/eval-dotenv-20261024-02/verification-02.json`）确认 `.env` 未挂入容器、密钥未进入产物和日志，冻结哈希与评分引用一致。本次配置验收限于 Linux ARM64，未重跑 K=5。
