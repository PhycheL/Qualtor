# 测试生成产品与评测入口运行说明

当前架构按 [D013](决策记录.md#d013-宿主机运行-pi生成产品独立交付修订-d004d010)：`agents/` 是可独立交付产品，宿主机 pi 生成并修复，Docker 编译验证；`evaluator/run.py` 组织批量实验与独立评分。产品用法和公开任务字段见 [产品 README](../agents/README.md)，运行边界见 [产品接口](接口与运行边界.md)。

第 1–6 节是现行操作方法；其后按日期保存验收记录。历史版本、测试数量和路径只说明对应那次执行。

## 1. 准备环境

宿主机需要 Python 3.9+、Node 23.6+、npm 和 Docker。当前验证环境为 macOS ARM64 / Node 26.12.0，C++ 执行环境为 Linux ARM64。首次安装需要联网。

```bash
python3 agents/setup.py --output runs/product-setup-<唯一编号>
python3 evaluator/toolchains/toolchains.py --toolchain clang
python3 evaluator/toolchains/toolchains.py --skip-build
```

产品安装负责宿主机 pi 与 GCC 镜像；评分另外需要 Clang/Mull。只重建宿主机 pi 用 `--pi-only`，只构建 GCC 用 `--gcc-only`。旧的 `--toolchain generator` 和生成镜像入口已移除。pi 按锁文件安装，模型目录按源码中固定摘要下载，构建不刷新实时模型目录；记录系统、架构、Node、源码、构建产物、依赖内容和搜索工具指纹。更换宿主机运行环境后重新安装。

安装器会先执行缓存搜索工具的 `--version`；旧平台二进制或损坏缓存无法运行时，移除失效文件，再查找当前宿主机工具或下载适配版本。

## 2. 模型和连接配置

模型配置在 `agents/configs/<name>/config.json`；连接文件默认是 **`agents/.env`**，示例见 [agents/.env.example](../agents/.env.example)。首次配置：

```bash
cp agents/.env.example agents/.env
chmod 600 agents/.env
```

已有配置直接编辑，避免覆盖。默认字段为 `QUALTOR_API_BASE_URL` 和 `QUALTOR_API_KEY`。产品与评测入口均支持 `--env-file /absolute/path/to/connection.env`。无需 export，读取位置不依赖启动目录；文件缺失或字段为空时失败，不回退到旧环境变量。字面解析不执行 shell 或插值。

凭证只传给宿主机 pi；编译和评分容器均不接收密钥，连接文件不复制到运行产物。`.env` 中其他字段不导出。没有配置 `cost_per_million` 时 USD 为 `null`，仍统计 token、调用次数、时间与修复轮次。

## 3. 产品与批量评测

只生成测试，使用公开任务：

```bash
python3 agents/run.py --task /path/to/public-task.json --output /path/to/new-result --config default
```

完整题目含隐藏评分字段，不能直接传给产品；评测入口负责投影公开任务。运行五次生成和独立评分：

```bash
python3 evaluator/run.py --config default --tasks gildedrose-update-quality \
  --trials 5 --jobs 1 --run-id eval-<唯一编号>
```

`--tasks all` 选择全部题目，`--set dev` 或 `acceptance` 筛选集合。每个 trial 使用新工作区，产品内部最多三次完整生成尝试。入口会检查评测模块的校准状态与指纹，必须为 passed；题目还必须已准入（`benchmark/admission.json`，D016）：批量选题时跳过未准入的题，点名未准入的题直接报错。冒烟或新题试跑加 `--allow-unadmitted`，结果不能用于正式比较。首次使用或代码、校准材料、镜像变化后，按[评测运行说明](评测运行说明.md#4-校准评测模块)执行完整校准；条件未变时复用已有校准。正常完成记为 completed；异常或基础设施重试耗尽时，D012 取消尚未开始的 trial，等待已开始项结束并保留结果，整轮记为 failed。

用户在生成期间发送 Ctrl+C / SIGTERM 时，评测入口停止派发并向正在生成的产品进程转发取消。产品清理 pi 和编译容器，记录 `cancelled`，保留已有产物与已记录成本，不重新生成也不进入评分；整轮记为 failed。已经进入独立评分的 trial 完成后保留结果。这与 D012 的基础设施故障策略分开处理。

## 4. 编译反馈与测试快照

pi 在宿主机工作区只看到允许的源码副本、TASK.md、tests/ 和 feedback/。文件工具通过白名单和路径检查限制读写；这不构成针对恶意 pi 进程的操作系统沙箱。生成的 C++ 在禁网、只读源码和只读测试快照的容器内执行，日志目录受容器私有父目录保护。

每次 `build_and_test` 编译前保存本轮测试快照及文件哈希，Docker 使用这份快照编译和运行；Agent 后续修改工作区里的测试，不改变已保存的快照。第 1 次快照同时保存到 `first/`，不计修复；以后每次编译消耗一轮。每轮保存完整编译输出、退出码和 GoogleTest 报告，工具返回摘要、所有失败名称、日志位置及剩余预算。Agent 可读取 `feedback/` 中的完整内容。生成结束时另存最终测试快照到 `final/`；没有编译时 `first/`、`final/` 都使用结束时内容。

编译和断言失败属于正常生成反馈；API/进程/编译服务基础设施错误才触发从空工作区重试。连续 900 秒无进展触发看门狗，编译期间暂停看门狗并由编译阶段及容器超时保护。详细状态、限额和退出码见[产品接口](接口与运行边界.md#结束与重试)。最终快照可能包含最后一次编译后的修改，因此是否有效仍由生成结束后的独立评测确认。

## 5. 结果、成本与补评

评测输出位于 `runs/<run-id>/trials/<task-id>/trial-<k>/`。`result.json` 是产品生成结果，`trial.json` 增加评分摘要；`first/`、`final/` 含测试快照和 SHA-256 清单。`attempts/` 是一次生成内的编译记录，`generation-attempts/` 是所有完整生成尝试；最后一次的副本位于 trial 根，原始证据保留。

`run.json` 记录配置、产品/pi/源码指纹、模型与 API 地址、镜像、评测模块版本和校准状态；不记录密钥。D014 保留历史 `score/<版本>/` 目录及 schema 1 的 `scorer` 字段；当前源码和 CLI 均使用 assessment 命名。pi 的实际请求仅审计模型名、reasoning_effort 和 thinking 类型。成本只统计完整 assistant 消息，包含错误重试，首次成本截止首次编译请求开始时间；从未编译时取生成结束时间。可重新提取单次生成成本：

```bash
python3 agents/generator/cost.py runs/<run-id>/trials/<task-id>/trial-1/generation-attempts/attempt-1 --unpriced
python3 evaluator/assessment/evaluate.py --rescore <旧run-id>
python3 evaluator/assessment/aggregate.py summarize --runs <run-id> --assessment-version "$(cat evaluator/assessment/VERSION)" --phase final
```

补评使用已保存的测试快照，核对文件哈希后新增评分版本目录，保留旧结果。生成产物结构见 [产品 README](../agents/README.md)，评测结果路径见 [评测运行说明](评测运行说明.md)。
