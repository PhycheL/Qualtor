# 查证记录

## 结论

- **研究版本**：`packages/ai`，npm 包 `@earendil-works/pi-ai` 1.2.0，本地提交 2d147a114。该目录与上游发布提交 06a466935（Release v1.2.0）只差两行更新日志，结论适用于 1.2.0 发布版。
- **正文写入的能力都有实际使用者**：统一请求、换模型、思考档位、模型目录、凭证与登录、中途系统消息、失败分类，都能在 pi-agent-core、pi-coding-agent 或 pi-durable 的源码中找到调用（见下文“使用者”）。
- **有几项能力未写入正文**：它们只出现在 README、测试、示例或默认不启用的功能里，见下文“未写入正文的能力”。
- **README 与源码有一处冲突**：README 说换模型时上一个模型的思考内容会用 `<thinking>` 标签包裹；源码自 16e142ef7（2026-01-08）起改为普通文字。正文按源码写。
- **背景部分依据作者事后的说明**：作者自述的动机来自 2025-11 的文章，不是 2025-08 建包时的记录；2026-06 的接口迁移没有对应的 PR 或 issue，只有提交和设计文档。

## 使用者

只列正文用到的事实。行号对应提交 2d147a114。

- **统一请求**：pi-agent-core 每轮通过宿主注入的请求函数发请求（`packages/agent/src/agent-loop.ts:396-407`）。编码代理注入的函数调用自己的模型运行时，后者实现 pi-ai 的 `Models` 接口并包装 `createModels()`（`packages/coding-agent/src/core/sdk.ts:420-436`、`model-runtime.ts:172-226`）。压缩摘要、分支摘要也走同一函数（`compaction/compaction.ts:619-639`）。
- **换模型**：`setModel` 只替换模型、记录切换，对话不变（`packages/coding-agent/src/core/agent-session.ts:2502-2522`）。各接口格式实现发送前调用 `transformMessages`（`packages/ai/src/api/transform-messages.ts`）。
- **思考档位**：pi-agent-core 把档位转为 `reasoning` 选项（`packages/agent/src/agent-loop.ts:186-200`）。编码代理用 `clampThinkingLevel`、`getSupportedThinkingLevels` 限制和列出档位（`sdk.ts:277`、`agent-session.ts:2637-2710`）。
- **模型目录与刷新**：编码代理注册全部内置服务商，并叠加 pi.dev 远程目录（`remote-catalog-provider.ts:14-16`，最多每 4 小时刷新一次）。刷新结果存入 `models-store.json`（`packages/coding-agent/src/core/models-store.ts:47`）。
- **凭证与登录**：
  - `/login` 调用 `ModelRuntime.login`，再进入 `Models.login`（`interactive-mode.ts:6327-6346`、`model-runtime.ts:826-846`）。
  - `auth.json` 由实现 `CredentialStore` 的 `AuthStorage` 读写，读写时用 proper-lockfile 加锁（`auth-storage.ts:9`、`328`）。
- **中途系统消息**：
  - pi-agent-core 在每次请求前把工具变化写成 `toolsAdded`/`toolsRemoved`（`agent-loop.ts:321-375`）。
  - 编码代理只追加变化的提示段落（`agent-session.ts:1742-1754`）。
- **失败分类**：
  - 超长时压缩后重发一次（`agent-session.ts:3026-3062`）。
  - 可重试错误按设置自动重试（`agent-session.ts:3784-3801`），默认最多 3 次、基准 2 秒（`settings-defaults.ts:17-25`）。
  - 编码代理不设置请求级重试次数，pi-ai 的请求级重试默认为 0（`packages/ai/src/utils/provider-retry.ts:107-112`）。
- **工具参数校验**：pi-agent-core 执行工具前调用 `validateToolArguments`（`agent-loop.ts:725-728`）；pi-durable 同样调用（`packages/durable/src/harness/tool.ts:241-247`）。
- **兼容入口仍在使用**：编码代理有 12 个源文件从 `@earendil-works/pi-ai/compat` 导入。真正依赖旧全局行为的是以下几处：
  - 扩展导入 pi-ai 根入口时被映射到兼容入口（`extensions/loader.ts:91-115`）；
  - models.json 新服务商的请求经兼容入口的全局登记表找到实现（`provider-composer.ts:589-602`）；
  - llama.cpp 扩展用全局 `stream`/`streamSimple`（`extensions/llama/provider.ts:288-289`）；
  - 未传请求函数的 `Agent` 回退到全局 `streamSimple`（`sdk.ts:40-46`）。

## 未写入正文的能力

- **延后取回的回复**（请求时要求服务商在后台继续生成，之后凭句柄取回结果）：pi-durable 实现了完整的轮询与取消，但 pi-ai 中只有测试用的 faux 服务商会返回这种句柄，没有真实服务商实现（`packages/ai/src/providers/faux.ts:311-320`；`api/` 下无实现）。
- **图像生成与分类**：只能从代码模式脚本和扩展调用。编码代理的代码模式扩展默认不启用（`packages/coding-agent/src/extensions/codemode/index.ts:31-44`），图像生成只有 OpenRouter 一家。对初识报告属于旁支。
- **`pi-ai` 命令行**：只能做 OAuth 登录并把凭证写到当前目录的 `auth.json`，仓库内无人调用；编码代理用自己的 `/login` 和 `pi auth`。
- **faux 服务商**：只用于测试和示例。
- **浏览器中使用、遥测上下文、自定义 fetch**：仓库内没有使用者。浏览器使用按此前反馈不写入定位。
- **带服务商专属选项的 `Models.stream/complete`**：源码中无调用，只有扩展示例使用；主路径都用 `streamSimple/completeSimple`。

## 背景资料

- **作者文章**：Mario Zechner, “What I learned building an opinionated and minimal coding agent”, 2025-11-30，<https://mariozechner.at/posts/2025-11-30-pi-coding-agent/>。
  - 为什么不用 Vercel AI SDK：直接基于官方 SDK，以便完全掌控、接口面更小。
  - 各家 Completions 接口的差异：有的拒绝 `store` 字段，有的拒绝 `developer` 角色，思考内容放在不同字段。
  - 用量统计：有的服务商只在流末尾报告用量，请求中止后无法准确计费。
  - 跨服务商交接和中止：从一开始就是设计目标。
- **2026-06 接口迁移**：设计文档 `git show 216ba41fc:packages/agent/docs/models.md` 列出的目标是：
  - 只导入需要的服务商；
  - 导入服务商不产生全局注册；
  - 支持运行时刷新的模型清单；
  - 凭证由服务商解析，存储可以注入。

  迁移在 129eb460c（2026-06-23）完成。兼容入口自称将随编码代理的迁移删除，但 1.2.0 仍保留，编码代理仍在使用（见上文）。
- **限制**：联网材料由检索子 Agent 获取，主 Agent 按引文核对了措辞与本地源码是否一致，没有再次打开原网页；需以事实审计的复核为准。

## 仍未确认

- **pi-durable 的实际使用者**：它是独立发布的库，仓库内除自身的测试和示例外没有运行它的程序。正文只把它写成 pi-ai 的使用方之一，不展开。
- **仓库外的服务**：仓库外是否有服务（例如经 Radius 网关的模型）会返回延后回复的句柄，从源码无法判断。
- **第三方扩展**：第三方扩展对兼容入口的依赖程度，仓库内看不到。
