- **事实问题**：
  1. **中途系统消息中关于工具增删的结论错误（需修正）**
     - **问题**：正文说支持的模型“原地收到变更、开头缓存仍然有效”，并把工具增删和提示段落写在一起。这只对提示段落成立；读者会以为工具变更普遍不破坏缓存。
     - **原地增删需要的条件**：
       - 只有 Anthropic 官方服务商的模型，在 `supportsMidConvoToolChanges` 为真、且开头至少有一个工具时，才原地增删工具（`anthropic-messages.ts:1194-1196`、`1256-1266`；`generate-models.ts:1231-1239`）。
       - OpenCode、GitHub Copilot 转发的 Claude 模型，工具变更仍放在顶层。
       - 部分 OpenAI Responses 模型和 Kimi K3 只能原地追加；一旦出现移除或重定义，就改发完整列表（`transcript.ts:199-237`）。
       - 其余模型的工具一律放在请求顶层。README 第 1601 行写法相同。
     - **修正方向**：把“原地收到、缓存仍有效”限定为提示段落；注明工具增删只有部分模型能原地表达，其余情况会在请求开头换上完整的当前工具列表，开头缓存随之失效。
  2. **“默认不重发”对 Bedrock 不成立（轻微）**
     - **问题**：OpenAI、Anthropic、Azure、Google、Codex 适配器都关掉了 SDK 自带重试，按 `maxRetries` 处理，默认为 0。
     - **例外**：Bedrock 适配器创建 AWS 客户端时既不设 `maxAttempts`，也不读 `maxRetries`（`bedrock-converse-stream.ts:163-165`、`251`），因此沿用 AWS SDK 的标准重试，默认最多尝试 3 次。
     - **修正方向**：注明 Bedrock 例外。
  3. **“42 个服务商配置中支持工具调用的对话模型”略有夸大（轻微）**
     - **问题**：42 是内置服务商配置数，核对无误。但其中 TypeSafe 只登记分类模型（`providers/typesafe.ts:6-17`），对话模型实际来自 41 个配置。
     - **修正方向**：不要把数字 42 和“对话模型”直接绑在一起。
  4. **费用来源的表述不适用于 Radius 网关（轻微）**
     - **问题**：多数适配器按 token 数乘目录单价计算费用。但 Radius 使用的 `pi-messages` 接口直接采用后端返回的用量和费用，本地不再计算（`api/pi-messages.ts:193-210`）。
     - **修正方向**：加上限定。
- **引用问题**：无。来源 1–16 的路径和行号都能对上，并支持对应结论。
- **未确认项**：
  - Radius 后端返回的费用怎么算（账单数据还是同样的估算），本仓库无法确认。这只影响第 4 条的措辞，不影响判定。
  - 工具列表变化后各服务商缓存的具体失效程度属于各家服务的行为，没有逐家联网核对。第 1 条的依据是实现中顶层工具列表确实会变，以及 README 第 1601 行的说法，足以支持判定。

## 复核

- **判定**：通过。四处修订都与源码和一手资料一致，原来的四个事实问题均已解决，修订没有带来新的事实错误。
- **逐条结论**：
  - **中途系统消息**：成立。
    - “原地收到、缓存仍有效”只用于提示变更。
    - 工具增删只在部分模型上能原地表达，与实现一致（`anthropic-messages.ts:1195-1196`、`1262-1266`；`transcript.ts:199-237`）。
    - `supportsMidConvoToolChanges` 只在 `generate-models.ts:1233` 为 Anthropic 官方服务商设置。
  - **Bedrock 重试例外**：成立。
    - Bedrock 适配器不设 `maxAttempts`，也不读 `maxRetries`。
    - 锁定的 `@smithy/core` 3.33.3 中 `DEFAULT_MAX_ATTEMPTS = 3`。AWS 官方文档写明这是含首次请求在内的总尝试次数。
  - **42 个服务商配置**：成立。数字只指服务商配置；TypeSafe 只有分类模型的说明准确。
  - **费用来源**：成立。加“通常”后不再绝对；`pi-messages` 直接采用后端用量，Radius 服务商使用该接口（`radius.ts:1`、`33`）。
- **新问题**：
  - **引用缺口（轻微）**：Bedrock “默认最多尝试 3 次”缺出处。
    - 主 Agent 已在来源 [11] 补上 AWS 官方文档链接和 lockfile 位置（`package-lock.json:1553-1554`）。
  - **说明（不列为问题）**：另有几种针对特定情况的一次性重发，性质是兼容降级或换传输方式，不属于按次数重试，不影响结论：
    - Anthropic 严格工具集被拒时改用非严格工具重发一次（`anthropic-messages.ts:664-681`）；
    - 旧版 openai-codex 服务商 WebSocket 失败时改走 SSE（`openai-codex-responses.ts:295-370`）。

    主 Agent 采纳复核建议，把“重发请求……默认不重发”改为“重试……默认不重试”，避免读成穷尽说法。
- **未确认项**（均不影响判定）：
  - Radius 网关清单不按工具能力过滤（`radius-config.ts:61-68`），这些模型是否都支持工具调用，依赖网关自身和 README:5 的约定。
  - 工具列表变化后各服务商缓存失效的具体程度，属于各家服务的行为，没有逐家核对。
